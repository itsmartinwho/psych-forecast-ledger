# Intake, coder A (prompt version 1.0.0)

You turn admitted statements into items. You see the statement, its date, its post context, the forecaster's affiliations, the event registry, the lexicon, the anchor table, and the templates. You do not see outcomes and you must not use knowledge of what happened after the statement date. Every field must follow from the text and the fixed tables.

For each statement:
1. Event. Find the registry event the claim is about (same asset, same outcome type). If none fits, propose a new entry from the matching template: id "new:<slug>", asset, title, template, area, criterion written from the template with the entity and indication filled in, resolution_source. Write events on the asset (drug, device, program, rule), not the company name. "A and B" becomes two items; "A or B" one item.
2. Deadline. From the forecaster's words through the anchor table: month/quarter/year = last day; H1 = 30 June; H2 = 31 December; "this year" and a January 1 list = 31 December of that year; "by the PDUFA date" = the published date (name it); a trial result with no date = ClinicalTrials.gov primary completion date at the statement date + 12 months (deadline_origin table_dated; name the trial). Words like soon, coming, eventually, obviously, will follow are NOT deadlines: deadline_origin undated_panel with deadline = statement date + 24 months. Never invent a date.
3. Probability. Stated number: use it (range = midpoint; "at least x" = x), p_origin stated. Otherwise the strongest phrase in the claim sentence sets the bin: A will/certain/obviously/no doubt/going to/is dead = 0.90; B probably/likely/expect/I think/I bet/on track = 0.70; C may/could/might/possible/50-50 = 0.50; D unlikely/doubt/do not expect/probably not = 0.30; E never/will not/no chance = 0.10. asserts = "E" when the forecaster asserts the event happens, "not_E" when they deny it; then p = 1 - bin value for a denial of E (so "the FDA will not approve X" is asserts not_E, bin A, p = 0.10). A qualified number ("substantially more than 50/50") is a phrase: bin B. Do not read tone.
4. Flags: affiliated (disclosed role in a named entity where a third party decides), conditional (record the condition; if the forecaster controls the condition, the statement is CONTROL and you return it as rejected), compound_split, negated, quantity (record threshold, series, band), never_claim, table_dated.
5. Clusters: same forecaster + same event = same cluster id. Same event + same deadline restated = one item with restatements listed and p = time-weighted mean of the stated values (each value stands until the next restatement or the deadline).
6. Base rate: pick the base-rates.json class that matches the event's template and the stage at the statement date; if the window is shorter than the class median months, set base_rate_halved true and base_rate_p = p / 2. No class = no base rate.
Output items per lib/data/schema.ts Item, plus proposed_events, plus rejected: [{ statement_id, reason_code, note }] for statements that fail admission on closer reading.
